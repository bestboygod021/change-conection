# نت‌اسپلیت (NetSplit)

یک برنامه‌ی کوچک ویندوزی برای **تفکیک اتصال اینترنت بین اکانت‌های مختلف گوگل کروم**.

با یک دکمه انتخاب می‌کنید که هر اکانت کروم **با فیلترشکن** باز شود یا **بدون فیلترشکن**؛ هر دو هم‌زمان.

```
┌─ اکانت کاری ─────────────┐   ┌─ اکانت شخصی ────────────┐
│ [مستقیم][با فیلترشکن][ویندوز]│   │ [مستقیم][با فیلترشکن][ویندوز]│
│      [ باز کردن کروم ]   │   │     [ باز کردن کروم ]    │
└──────────────────────────┘   └──────────────────────────┘
        ↓ پروکسی 127.0.0.1:10808        ↓ مستقیم (بدون پروکسی)
```

---

## چطور کار می‌کند؟

کروم اجازه می‌دهد برای هر **نمونه** یک پروکسی جدا تعیین کنید. نت‌اسپلیت برای هر اکانت:

1. یک **پوشه‌ی پروفایل جدا** می‌سازد (`--user-data-dir`)، پس هر اکانت لاگین گوگل خودش را دارد؛
2. پروکسی همان اکانت را با `--proxy-server` تعیین می‌کند:

| حالت | چه اتفاقی می‌افتد | فلگ |
|---|---|---|
| **با فیلترشکن** | ترافیک از پروکسی فیلترشکن رد می‌شود | `--proxy-server=http://127.0.0.1:10808` |
| **مستقیم** | پروکسی کاملاً نادیده گرفته می‌شود، **حتی اگر فیلترشکن روشن باشد** | `--proxy-server=direct://` |
| **پیش‌فرض ویندوز** | هرچه در تنظیمات پروکسی ویندوز ست شده | (بدون فلگ) |

نکته‌ی کلیدی همان `direct://` است: چون پروکسیِ فیلترشکن معمولاً به‌صورت سراسری در ویندوز ست می‌شود، بدون این فلگ «هر دو اکانت با فیلترشکن» می‌شدند.

**بدون نیاز به دسترسی ادمین، بدون درایور، بدون دستکاری تنظیمات شبکه.**

## نصب و اجرا

### راه ساده (پیشنهادی): ساخت فایل نصب روی ویندوز

1. [Node.js نسخه‌ی LTS](https://nodejs.org/) را نصب کنید (یک‌بار).
2. روی `build.bat` دوبار کلیک کنید (یا در PowerShell در پوشه‌ی پروژه بزنید `.\build.bat`).
3. خروجی در پوشه‌ی `release\` ساخته می‌شود:
   - `NetSplit-Setup-1.0.0.exe` → نصب‌کننده (میان‌بر دسکتاپ هم می‌سازد)
   - `NetSplit-Portable-1.0.0.exe` → بدون نصب، فقط اجرا

دستوری:

```powershell
npm install
npm run dist:win        # نصب‌کننده + نسخه‌ی پرتابل
```

### راه توسعه (اجرای مستقیم بدون ساخت)

```bash
npm install
npm start
```

## استفاده (سه قدم)

1. **فیلترشکن را روشن کنید.** برنامه خودش پورت پروکسی را پیدا می‌کند (از پروکسی سیستم در رجیستری ویندوز، و در غیر این صورت با گشتن پورت‌های رایج: `10808, 10809, 1080, 7890, 7891, 1087, ...`). در نوار بالا می‌بینید: «فیلترشکن فعال: 127.0.0.1:10808».
2. **برای هر اکانت یک حالت بزنید** — «با فیلترشکن» یا «مستقیم».
3. **«باز کردن کروم» را بزنید.** بار اول، در هر کروم یک‌بار وارد اکانت گوگل موردنظر شوید. از دفعه‌های بعد همان اکانت با همان اتصال باز می‌شود.

اگر کرومِ یک اکانت باز باشد و حالتش را عوض کنید، برنامه خودش می‌پرسد که «ببندم و دوباره باز کنم؟» — چون پروکسی کروم فقط موقع باز شدن تعیین می‌شود.

## تنظیمات

| گزینه | توضیح |
|---|---|
| مرورگر | خودش `chrome.exe` را پیدا می‌کند (Edge و Brave هم پشتیبانی می‌شوند). اگر پیدا نکرد، دستی انتخابش کنید. |
| آدرس پروکسی فیلترشکن | خالی = پیدا کردن خودکار. وگرنه مثلاً `127.0.0.1:7890` یا `socks5://127.0.0.1:1080`. |
| پوشه‌ی پروفایل‌ها | `%APPDATA%\NetSplit\ChromeProfiles\<نام اکانت>` |

فایل تنظیمات برنامه: `%APPDATA%\NetSplit\config.json`

---

## پرسش‌های رایج

**فیلترشکنم حالت TUN دارد (مثل Warp یا TUN در v2rayN). کار می‌کند؟**
در حالت TUN، ترافیک در لایه‌ی شبکه و از روی آداپتور مجازی رد می‌شود و هیچ پروکسی‌ای وجود ندارد که بشود دورش زد؛ در این حالت «مستقیم» هم از تونل رد می‌شود. راه‌حل: در فیلترشکن، **حالت پروکسی سیستم (HTTP/SOCKS)** را روشن کنید و TUN را خاموش کنید. آن‌وقت «با فیلترشکن» از پروکسی و «مستقیم» با `direct://` واقعاً مستقیم می‌شود.

**پروکسی را پیدا نکرد؟**
در تنظیمات، آدرس پروکسی را دستی وارد کنید. پورت را در فیلترشکن خودتان می‌بینید (v2rayN معمولاً `10808`، Clash معمولاً `7890`).

**اکانت‌هایم جابه‌جا می‌شوند؟**
نه. پوشه‌ی پروفایل هر اکانت فقط هنگام ساختش تعیین می‌شود؛ تغییر نام، لاگین‌ها را پاک نمی‌کند.

**حذف اکانت از برنامه، پروفایل کروم را پاک می‌کند؟**
نه. فقط از فهرست برنامه حذف می‌شود؛ پوشه‌اش در `%APPDATA%\NetSplit\ChromeProfiles` می‌ماند.

## ساختار پروژه

```
src/
  main.js              پنجره و هندلرهای IPC
  preload.js           پل امن بین صفحه و هسته
  renderer/            رابط کاربری (فارسی، راست‌به‌چپ)
  lib/
    config.js          اکانت‌ها و تنظیمات
    chrome.js          پیدا کردن مرورگر + ساخت آرگومان‌های اجرا
    proxy.js           تشخیص پروکسی فیلترشکن
    launcher.js        اجرا/بستن پروسه‌ی کروم هر اکانت
    store.js           چسباندن این‌ها به هم
test/                  ۷۰ تست (node --test)
demo/                  نسخه‌ی نمایشی در مرورگر
```

### تست‌ها

```bash
npm test
```

۷۰ تست که منطق واقعی برنامه را اجرا می‌کنند: ساخت آرگومان‌های کروم برای هر حالت، تشخیص پروکسی (روی یک سرور TCP واقعی)، ذخیره‌ی تنظیمات، مدیریت پروسه‌ها، تطابق کانال‌های IPC بین `preload` و `main`، و رفتار رابط کاربری با jsdom.

### دیدن رابط کاربری بدون ویندوز

```bash
npm run demo      # → http://localhost:4173
```

همان فایل‌های واقعی رابط کاربری با یک پل شبیه‌سازی‌شده؛ برای دیدن ظاهر و رفتار دکمه‌ها.

## محدودیت‌های صادقانه

- این برنامه **فیلترشکن نیست**؛ فقط تعیین می‌کند کدام اکانت از پروکسیِ موجود استفاده کند و کدام نه.
- پروکسی کروم **هنگام باز شدن** تعیین می‌شود؛ برای تغییر اتصال، کرومِ آن اکانت باید بسته و دوباره باز شود (خود برنامه پیشنهادش را می‌دهد).
- تفکیک اتصال برای **مرورگر** است، نه برای بقیه‌ی برنامه‌های ویندوز.
